# 网页账号模式（开发中）

目标是打开网页后先注册或登录，成功后进入首页；报告、自选股、对话、持仓、告警等数据按账号隔离。第一个注册账号为管理员，接收当前单用户数据。模型与新闻搜索等 API Key 由管理员统一配置，其他账号只使用服务，不查看密钥。

## 当前实现边界

账号模式通过 `.env` 的 `WEB_ACCOUNTS_ENABLED=true` 显式开启，默认关闭。已经实现用户名密码注册、登录、签名会话、退出以及首个管理员本机创建。用户名允许 3–32 位英文字母、数字、下划线；密码至少 8 位。若已有旧管理员密码，首个管理员注册必须输入该密码。首次注册只接受服务器的本机连接，不信任代理传入的 IP 头。旧的 `ADMIN_AUTH_ENABLED` 单密码模式在账号开关关闭时继续使用。

普通账号登录后进入与管理员相同的原工作台，可使用首页、AI 分析和问股等入口；设置页只显示个人通知渠道和定时推送，系统 API Key、搜索、SMTP 和全局调度设置只有管理员能查看和修改。自选股保存在按账号区分的 `web_watchlist_items` 表中；通知渠道与定时推送任务分别保存在 `web_notification_channels`、`web_scheduled_push_tasks`，地址加密保存。定时推送任务按服务器时间每天执行，可为每个任务选择股票、邮箱或飞书/钉钉/Discord/Slack Webhook，并单独开启 AI 分析和新闻摘要。

原项目数据库和其他多数业务表仍是全局共享的，多账号数据归属迁移尚未完成；分析历史、聊天会话、回测、告警、决策信号和用量等能力在完成 owner 绑定前不适合对外开放给多个普通账号。现有旧记录没有复制或改写；首个管理员直接管理原有记录。服务端会拒绝普通账号读取系统配置，不能依赖前端隐藏来保护密钥。

因此当前版本不适合对外提供完整的多用户产品。后续需逐项为报告、任务/SSE、聊天、持仓、回测、告警、决策信号、用量与设置建立用户归属，并验证按 ID 查询和删除不会跨账号。完成后才能放开普通账号使用完整工作台。

## 个人通知渠道与定时推送

普通账号登录后在首页进入「设置」，可保存自己的收件邮箱或飞书、钉钉、Discord、Slack 官方 HTTPS Webhook。每个渠道保存一个地址；再次保存相同渠道会替换旧值。定时推送任务单独保存任务名称、服务器时间、股票代码、渠道地址和 AI/新闻开关，AI 分析和新闻摘要至少开启一项。API 只返回脱敏地址，管理员的系统设置和模型、搜索 Key 不向普通账号开放；邮件发送仍需管理员在系统设置里配置 SMTP 发信账号。

通知地址加密存于数据库，密钥文件位于 `DATABASE_PATH` 所在目录的 `.notification_secret`。部署、迁移与备份时，数据库和这个文件须一起保存；密钥丢失后已保存的通知地址无法解密，需用户重新填写。此文件不可提交到 Git。

## 回滚

在 `.env` 移除 `WEB_ACCOUNTS_ENABLED=true` 并重启服务，即回到原有单密码模式。账号表会保留，现有业务数据不受影响。不要删除旧管理员密码文件或数据库。
